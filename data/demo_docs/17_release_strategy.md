# AtlasDesk v2 滚动发布与观察窗口

## 发布前提
本文是虚构演示资料，说明 AtlasDesk v2 的发布流程，不代表已经达到零中断发布。发布前核对目标版本、配置差异、迁移可逆性及备份恢复记录。涉及从旧版升级时必须遵循《迁移清单》，不能把普通同版本滚动替换步骤套用到大版本迁移。

## 替换顺序
先停止目标副本接收新流量，等待正在执行的请求结束，再替换程序。滚动发布最多允许一个 API 副本不可用；新副本连续三次 readiness 成功后才接入流量，并设置三十秒优雅关闭窗口。存活探针成功不足以接流量，数据库或 Redis 不可用时应保持未就绪状态。

## Worker 配合
API 和 Worker 分开发布，更新 Worker 前先停止领取并排空已领取任务。发布期间保留事件编号，防止重启生成新编号导致消费者无法去重。即使两个进程都已更新，也要检查待处理事件、最终失败事件和外部回调，不能只确认进程仍然存活。

## 观察与决策
创建接口错误率和延迟超过《回滚手册》的连续窗口阈值时暂停发布，先检查依赖再评估回滚。告警不等于自动回滚；是否恢复旧版还受到业务是否已经写入和迁移可逆性的限制。演示验收同时记录探针、冒烟结果与观察窗口数据，不能将发布成功提示代替完整验证。

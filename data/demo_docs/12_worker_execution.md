# AtlasDesk v2 Worker 执行与任务状态

## 适用范围
本文是虚构的 AtlasDesk v2 演示资料，描述异步通知执行约定，不代表已经测得的生产处理能力。API 与 Worker 分开部署；创建工单成功只表示业务记录已经提交，不表示外部通知已经送达。调用方需要分别核对工单状态与通知状态，不能把两者混为一次同步事务。

## 领取与确认
待处理事件先保存到 PostgreSQL，Redis 用于协调领取和短期执行状态。Worker 领取后记录事件编号、处理阶段与最后尝试时间，向外部地址发送通知。只有收到符合协议的成功响应后才确认投递完成。进程在外部接收成功、内部确认之前退出，恢复后仍可能再次投递同一事件。

## 重试与排空
通知采用至少一次投递，重试上限和退避序列沿用《常见故障》的约定。消费者必须按 event_id 去重，创建接口的幂等键不能代替这个步骤。维护或升级时先停止领取新任务，让已领取任务完成，再停止进程；未完成任务需要保留可恢复状态，不允许直接删除队列来消除积压。

## 恢复检查
Redis 重建后，根据数据库中的待处理事件恢复任务，再检查未确认通知。运维人员使用 request_id 关联 API 与 Worker 日志，记录重复投递和最终失败原因。联合阅读《备份与恢复》《Webhook 接收协议》，才能判断恢复后的通知是否完整。

# AtlasDesk v2 容量规划与连接预算

**规划边界**
本文为虚构演示资料，所有容量计算仅说明配置约束，不是压测结果，也不代表系统能够承受某个真实吞吐量。容量规划同时考虑 API、Worker、数据库、Redis 和对象存储；提高应用副本数并不一定提高整体能力，可能先耗尽共享依赖资源。

**数据库预算**
每个 API 副本的连接上限是池大小加溢出数量，默认十加五，共十五个。演示数据库最大连接数为一百，至少预留二十个给 Worker、运维和监控，因此 API 预算为八十。四个默认副本的峰值是六十；按连接数约束计算，五个是七十五，六个是九十，后者已经超过 API 预算。

**扩容决策**
上述计算只是必要条件，不能据此宣布五副本是最佳部署或已经通过压力验证。扩容前核对实际连接等待、请求延迟、队列深度和数据库负载；Worker 数量变化后重新计算其占用，不能长期把二十个预留视为不变的实际需求。需要增加连接池时先证明数据库仍有余量。

**测试记录**
压测记录请求组合、附件大小、租户数量、预热方式及持续时间，并分别报告正常请求和失败请求。每租户每分钟六百次的 API 配额属于限流策略，不等于服务实测吞吐能力。发布和回滚判断仍使用可观测性文档中的连续窗口，不能用短时峰值直接代替。

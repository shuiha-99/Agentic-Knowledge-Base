# AtlasDesk v2 可观测性与告警

## 日志
API 以 JSON 写标准输出。每条请求日志包含 request_id、tenant_id、route、status_code、duration_ms，不记录访问令牌、客户端密钥和完整请求体。
请求头 `X-Request-ID` 合法时沿用，否则生成新值。API 将 request_id 传递给 Worker，便于关联同一次业务请求的异步处理。

## 指标
监控请求量、5xx错误率、P50/P95延迟、数据库连接池等待、Worker队列深度。告警分母是同一时间窗内的请求总数，不把401和422记为服务端5xx错误。
创建工单5xx错误率连续五分钟大于2%时告警；P95延迟持续五分钟超过800毫秒时告警。这些阈值也是回滚评估的触发条件，但告警不等于自动回滚。

## 探针排障
存活探针成功而 readiness 失败时，先检查 PostgreSQL 和 Redis 连接。不要因为 `/healthz` 返回200就认定服务可以接收流量。
数据库连接等待升高时，联合检查 API 副本数、每副本连接池和数据库最大连接数，避免只增加应用连接池。

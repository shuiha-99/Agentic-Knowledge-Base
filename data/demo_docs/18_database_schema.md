# AtlasDesk v2 逻辑数据模型

**模型范围**
本文为虚构演示资料，给出问答和运维所需的逻辑关系，不是实际生产数据库的完整建表脚本。工单主体、工单事件、附件引用、幂等记录与通知确认记录具有不同生命周期，不能因为都与同一工单有关就合并成一个无版本的大字段。

**工单与事件**
工单记录保存所属租户、标题、描述、优先级和当前状态；事件记录保存工单编号、租户、事件类型和发生顺序。迁移清单中明确新增的 ticket_events 用于记录事件。查询详情读取当前业务状态，异步通知读取待处理事件，两者不能通过清空 Redis 来直接删除或重置。

**关联约束**
附件引用包含所属工单与对象版本，恢复时需要同时校验引用和对象存在性。幂等记录关联租户、请求键、请求体摘要和首次结果，在约定窗口内用于识别重复创建。通知确认关联稳定事件编号，不能拿创建请求的幂等记录替代消费者的事件去重记录。

**变更边界**
修改表结构前检查旧程序能否读取、新程序能否容忍旧数据，并单独验证数据回填。迁移清单明确的可逆范围不能自动推广到任意附属表或后续变更。联合阅读《Schema 变更策略》和《回滚手册》，以实际迁移和业务写入边界决定恢复路径，不凭表名判断一定可以回退。

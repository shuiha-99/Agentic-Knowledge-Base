# AtlasDesk v2.0 回滚手册

## 回滚决策
发布后十分钟内，如果创建工单接口的错误率连续五分钟大于 2%，或 P95 延迟持续五分钟超过 800 毫秒，应暂停发布并评估回滚。值班人员先确认依赖故障，避免把数据库故障误判为程序版本问题。

## 尚未恢复写入
如果迁移完成后还没有恢复业务写入，可以停止 v2 API 与 Worker，运行 `atlasdesk migrate --to 1.8` 执行可逆回迁，再恢复 v1 配置和程序。确认 `/health` 正常，最后恢复入口流量。

## 已恢复写入
如果 v2 已经接收新业务写入，禁止直接回迁或直接启动 v1。先关闭写入口、停止 Worker，导出新增业务数据；由数据库负责人决定修复前进，或恢复迁移前快照并人工补偿新增数据。
任何快照恢复都会覆盖快照之后的数据，因此必须记录恢复点和需要补偿的工单。回滚完成后执行创建、查询、权限校验与回调冒烟检查，并保留操作记录。

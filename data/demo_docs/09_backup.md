# AtlasDesk 备份与恢复

## 备份策略
PostgreSQL 每日02:00执行全量备份，保留7天；WAL归档每5分钟上传一次，保留7天。附件对象存储启用版本保留，保留期30天。
Redis 不是工单业务数据的唯一来源。重建 Redis 后可以从数据库恢复待处理业务，但需要检查未确认通知，允许出现重复投递。

## 恢复目标
演示运维目标为 RPO 不超过5分钟，RTO 不超过60分钟。这是目标值，不是已经通过生产演练验证的结果。
每月执行一次恢复演练，记录实际恢复点、耗时与校验结果。升级前必须验证备份可恢复，不能只检查备份任务显示成功。

## 恢复校验
恢复后核对工单数量、抽样详情、附件引用、租户边界及待发送通知。快照之后的新增数据需要业务补偿，恢复操作由数据库负责人执行。

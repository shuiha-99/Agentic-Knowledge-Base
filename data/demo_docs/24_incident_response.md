# AtlasDesk v2 故障响应与升级协作

## 接报与确认
本文为虚构演示资料，描述故障处理顺序。接到告警后先记录开始时间、影响接口、租户范围和关联号，确认是否正在发布或维护。创建接口错误率与延迟告警采用《可观测性与告警》的连续五分钟窗口，不把单个客户端参数错误直接升级为服务整体不可用。

## 分层定位
先检查入口与实例就绪状态，再检查数据库连接、Redis 和 Worker 积压。存活探针成功而就绪探针失败时优先调查依赖，不能反复重启 API 掩盖数据库问题。附件故障与通知故障分别追踪，不因工单详情仍可查询就宣布全部业务正常。

## 止损与变更
必要时暂停发布、限制写入口或停止 Worker 领取，记录措施及预期影响。回滚由值班人员结合依赖状态和数据写入边界评估，不能把告警自动等同于恢复旧版的授权。已产生新版写入时按照《回滚手册》保存新增数据并由数据库负责人决定后续路径。

## 恢复与复盘
恢复后执行创建、查询、权限、附件与回调冒烟，检查积压是否持续下降及重复事件是否得到去重。事件记录区分观察到的事实、待验证假设和实际采取的操作，避免把推测写成根因。复盘列出缺失监控、恢复耗时及后续责任项，不以一次成功请求代替完整恢复证据。

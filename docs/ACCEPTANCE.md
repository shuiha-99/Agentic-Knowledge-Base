# 功能验收与项目描述对应

以下是可复核的验收方法，不是全部已经通过的生产证明。测试替身验证控制流，真实模型实验验证模型行为，二者分别记录。

| 描述 | 实现位置 | 验收证据 |
|---|---|---|
| 文档解析到流式对话全链路 | ingestion/chunking/retrieval/graph/ui | 上传有依据文档，建库后得到含来源的真实模型流式回答 |
| 独立状态的主子图 | graph.py | 同时运行两个任务，私有检索状态不串任务，不传完整主会话历史 |
| 查询重写与自动拆解 | graph.py规划节点 | 简单题一个任务，跨文档题形成合理子任务；保留实际计划 |
| Send并行 | graph.py调度器 | 事件时间戳与测试证明分支执行重叠，结果按task_id完整聚合 |
| 依赖任务 | graph.py调度器 | 第二波使用前置任务结果，循环、缺失依赖及超上限任务有限结束 |
| 父子分层索引 | chunking/store/retrieval | 每个子块回查父块与原文，父块展开去重 |
| 合并和拆分碎片 | chunking.py | 测试短段、长段、中文标点、同章节合并与跨章节边界 |
| 混合检索与真实重排 | providers/retrieval | 真正Dense/Sparse向量、RRF候选与Cross-Encoder分数；与基线对照 |
| 文档生命周期 | retrieval/store | 相同内容去重、同名文档更新、删除后不可检索，写入失败不激活半成品 |
| interrupt_before澄清 | graph.py | 明确题不暂停；歧义题在clarify前暂停；新进程同thread_id继续 |
| Loop limit和Fallback | graph.py | 无证据、无改善、格式错误、超时、部分分支失败均有限结束 |
| 分层上下文压缩 | memory.py | 主图累计摘要、局部逐字证据提取，动态token预算，检查事实与约束保留 |
| 流式答案和引用 | graph/ui | token来自模型实际流；结束状态校验来源ID；UI展示原文 |
| 多会话及恢复 | graph/ui | 两个新浏览器初始thread_id不同；切换会话不串历史；恢复失败不丢澄清状态 |
| RAGAS | evaluation/独立worker | 真实评分包运行，固定配置与逐题记录；未知或失败指标不伪造 |

## 建议演示顺序

1. 导入`data/demo_docs`并查看父子块数量。
2. 问“v2创建工单需要哪些权限，参数错误返回什么？”展示单任务与引用。
3. 问“比较v1/v2部署与配置，说明升级后已经写入时如何回退。”展示实际拆题、多分支、版本边界。
4. 问“这个版本怎么升级？”等待澄清，输入“AtlasDesk v1.8升级v2.0”，确认同会话继续。
5. 问知识库没有的真实预算、薪资或未发布版本日期，检查是否明确缺少依据。
6. 打开安全文档中的恶意样例，确认系统没有执行文档指令。
7. 同名文档更新后再问对应事实，确认只使用激活版本；删除后确认无法继续检索该来源。
8. 回放长对话，检查是否实际触发压缩，再核对前期版本与写入约束。
9. 查看一份完整评测报告，解释样本数、失败数、数据边界和指标口径。

## 仍需实测后才能使用的表述

“0.87左右”“0.82”“压缩比稳定0.55～0.7”均属于待验证指标。项目代码和离线控制流测试通过不能替代这些实验。项目经历时间也应与实际开发记录一致；不能用现在完成的代码证明过去日期已经完成。

本地演示不直接证明企业上线、多租户权限、生产恢复可靠性或消息恰好一次。角色贡献与验收范围应按实际工作记录描述。
